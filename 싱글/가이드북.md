## 1. 제일 먼저: 어느 방법으로 실행할까?

| 입력 대상 | 권장 옵션 | 최적화 방식 |
|---|---|---|
| 적혈구 normal/variable/tilt/double/triple | `--method spectral` | Full GD100 + Spectral Periodic L-BFGS100 |
| Cameraman, Chelsea, Moon, Brick, Coins 등 | `--method pyramid` | Pyramid64 GD150 + SciPy L-BFGS-B 최대150 |
| 합성 장면을 입력하고 자동 선택 | `--method auto` | RBC → spectral, 기타 → pyramid |
| 동일 데이터에서 두 방식 비교 | `--method compare` | spectral과 pyramid를 각각 실행 |
| 주파수 보정 효과 비교 | `--method periodic` | Full GD100 + identity Periodic L-BFGS100 |

싱글 연구의 우선 대상은 적혈구다. 기존 일반 이미지 알고리즘은 버리지 않는다.
`auto`는 사용자가 명시한 대상 종류에 따른 규칙이지, 센서에서 물체의 종류를 분류하거나 가장 정확한 결과를 자동으로 고르는 AI가 아니다.
Chelsea/Checkerboard 등 모든 신규 입력에서 Pyramid가 항상 더 좋다고 입증된 것은 아니다.

## 3. 빠른 실행: 파장을 아는 경우 (Known)

`single`은 합성 위상 생성 → 센서 생성 → 역복원 → 정답과 비교를 한 번에 수행한다.

### 3.1 적혈구 3층 중첩, 660 nm (주력 연구)

```powershell
python -m 싱글.run single --scene triple --true-wavelength 660 --mode known --wavelength 660 --method spectral --output 싱글/결과/rbc_triple660_spectral
```

정답 파장은 생성에, `--wavelength`는 알려진 역복원 파장에 사용한다.
위 명령의 새 합성 장면은 과거 저장된 센서 배열의 정확한 재생이 아니다.
기존 0.077086 rad/49집단 결과를 그대로 얻는다고 가정하지 않는다.

### 3.2 다른 적혈구 조건

```powershell
python -m 싱글.run single --scene normal --true-wavelength 660 --mode known --wavelength 660 --method auto --output 싱글/결과/rbc_normal660
python -m 싱글.run single --scene variable --true-wavelength 660 --mode known --wavelength 660 --method auto --output 싱글/결과/rbc_variable660
python -m 싱글.run single --scene tilt --true-wavelength 550 --mode known --wavelength 550 --method auto --output 싱글/결과/rbc_tilt550
python -m 싱글.run single --scene double --true-wavelength 440 --mode known --wavelength 440 --method auto --output 싱글/결과/rbc_double440
```

| scene | 물리 모델 |
|---|---|
| normal | 동일 직경, 기울기 없는 적혈구 |
| variable | 직경 변화, 기울기 없음 |
| tilt | 직경·Hb 굴절률 대비·기울기 변화 |
| double | 최대 2층 중첩 |
| triple | 100개 적혈구, 50집단, 최대 3층 (특정 어려운 집단 포함) |

RBC는 합성 투영 두께 모델이다. 실제 3D 다중 산란이나 흡수를 구현한 것은 아니다.
660 nm 이외에서는 Hb 굴절률 대비의 비분산 근사를 사용하므로 실제 물리 분산 검증이 별도로 필요하다.

## 4. 파장을 모르는 경우 (Blind)

```powershell
python -m 싱글.run single --scene triple --true-wavelength 660 --mode blind --method spectral --output 싱글/결과/rbc_blind660
python -m 싱글.run single --scene tilt --true-wavelength 553 --mode blind --method auto --output 싱글/결과/rbc_blind553
python -m 싱글.run single --scene camera --true-wavelength 595 --mode blind --method pyramid --output 싱글/결과/camera_blind595
```

- `--true-wavelength`: 합성 데이터 생성용이며 Blind 역복원에 전달되지 않는다.
- Blind에서는 `--wavelength`를 넣으면 오류가 발생한다.
- 440~660 nm, 10 nm 간격 flat-phase reference 탐색 → 가장 좋은 coarse 후보 주변 1 nm 간격 탐색 → 선택 파장으로 위상 복원.
- 실제 파장이 후보 범위/격자 밖이면 정확히 맞추는 보장이 없다. 비정수 파장도 생성할 수 있지만 현재 탐색은 정수 nm다.
- `blind_scan.json`에서 후보별 상대 센서 오차를 확인한다.
- 이 방식은 실험적 휴리스틱이다. 위상과 파장의 joint inversion, 완전한 미지 파장 복원 또는 다른 파장 일반화가 입증되지 않았다.

## 5. 같은 센서에서 알고리즘 비교

```powershell
python -m 싱글.run single --scene triple --true-wavelength 660 --mode known --wavelength 660 --method compare --output 싱글/결과/compare_rbc660
python -m 싱글.run single --scene chelsea --true-wavelength 660 --mode known --wavelength 660 --method compare --output 싱글/결과/compare_chelsea660
python -m 싱글.run single --scene checkerboard --true-wavelength 660 --mode blind --method compare --output 싱글/결과/compare_checker_blind660
```

`compare`는 합성 센서를 한 번만 생성하고, Blind인 경우 파장도 한 번만 탐색한다.
두 방법이 같은 관측 배열과 같은 파장을 사용한다. 서로의 위상 결과를 초기값으로 쓰지 않는다.
결과는 `inverse/spectral/`, `inverse/pyramid/`, `inverse/comparison_evaluation.json`에 저장된다.
반복 예산은 spectral 100+100, pyramid 150+최대150으로 다르므로 RMSE와 반복수/forward/adjoint 횟수를 함께 비교한다.
정답 기반으로 두 결과 중 하나를 실제 복원기의 최종 해로 자동 선택하지 않는다.

### Spectral preconditioner의 효과만 비교

동일한 센서에 `spectral`과 `periodic`을 각각 실행한다. 6절의 분리 실행 방식으로 하나의 관측을 두 번 사용한다.
`periodic`은 FFT preconditioner 대신 identity를 사용하며 Full GD100 + Periodic L-BFGS100 구조는 동일하다.

## 6. Generate / Recover / Evaluate 분리 실행

가장 중요한 재현 방식: 정답 파일 없이도 Recover가 돌아간다.

```powershell
# 1. 합성 센서와 정답을 분리 생성
python -m 싱글.run generate --scene triple --true-wavelength 660 --seed 672906 --output 싱글/결과/obs_rbc660

# 2. 동일 센서에 Known Spectral
python -m 싱글.run recover --sensor 싱글/결과/obs_rbc660/sensor_only.npz --mode known --wavelength 660 --method spectral --output 싱글/결과/inv_spectral660

# 3. 동일 센서에 Known Periodic
python -m 싱글.run recover --sensor 싱글/결과/obs_rbc660/sensor_only.npz --mode known --wavelength 660 --method periodic --output 싱글/결과/inv_periodic660

# 4. 두 복원 결과 각각 평가
python -m 싱글.run evaluate --truth 싱글/결과/obs_rbc660/private_truth.npz --sensor 싱글/결과/obs_rbc660/sensor_only.npz --recovery 싱글/결과/inv_spectral660
python -m 싱글.run evaluate --truth 싱글/결과/obs_rbc660/private_truth.npz --sensor 싱글/결과/obs_rbc660/sensor_only.npz --recovery 싱글/결과/inv_periodic660

# 5. 동일 센서에 Blind 비교 (파장 한 번 탐색)
python -m 싱글.run recover --sensor 싱글/결과/obs_rbc660/sensor_only.npz --mode blind --method compare --output 싱글/결과/inv_compare_blind
python -m 싱글.run evaluate --truth 싱글/결과/obs_rbc660/private_truth.npz --sensor 싱글/결과/obs_rbc660/sensor_only.npz --recovery 싱글/결과/inv_compare_blind
```

`--seed`는 센서 noise seed, `--geometry-seed`는 독립 RBC 형상/배치 seed이다. 예: `python -m 싱글.run single --scene triple --geometry-seed 20261128 --seed 672907 --output 싱글/결과/rbc_independent`. 새로운 triple seed는 생성기가 배치 조건을 만족해야 하며 실패 시 다른 seed를 명시하고 기록한다.

## 7. 실제 센서 측정 파일을 복원하는 경우

입력 NPZ의 키가 `sensor`인 3000×3000 유한·비음수·비영점 intensity 배열이어야 한다.
실제 카메라 데이터는 별도 보정(black level, 센서 응답, 정렬 등)이 필요할 수 있다. 임의 크기 데이터를 3000×3000으로 늘려 물리 격자를 맞춘 척하지 않는다.

```python
# 예: 이미 물리 좌표와 보정이 맞는 intensity.npy를 NPZ로 포장
import numpy as np
y = np.load("intensity.npy", allow_pickle=False)
assert y.shape == (3000, 3000)
assert np.isfinite(y).all() and (y >= 0).all() and (y > 0).any()
np.savez_compressed("sensor_only.npz", sensor=y.astype(np.float64))
```

```powershell
# 실험 대상이 적혈구이며 파장이 알려진 경우
python -m 싱글.run recover --sensor sensor_only.npz --mode known --wavelength 660 --method auto --object-type rbc --output 싱글/결과/real_rbc660

# 일반 물체이며 파장을 모르는 경우
python -m 싱글.run recover --sensor sensor_only.npz --mode blind --method auto --object-type general --output 싱글/결과/real_general_blind

# 대상 분류를 모르거나 두 방법을 함께 확인하고 싶은 경우
python -m 싱글.run recover --sensor sensor_only.npz --mode known --wavelength 660 --method compare --output 싱글/결과/real_compare660
```

`recover --method auto`에서는 `--object-type rbc|general`이 필수다.
`recover`에서 method를 생략하면 이전 명령과 호환되도록 spectral을 선택한다.
실제 측정에서는 정답 위상을 모르는 것이 정상이다. `evaluate`를 억지로 실행하거나 Sensor L2를 phase RMSE로 해석하지 않는다.
`recovered.npz`의 `phase` 키를 열어 위상을 확인할 수 있다.

```python
import numpy as np
import matplotlib.pyplot as plt
with np.load("싱글/결과/real_rbc660/recovered.npz", allow_pickle=False) as z:
    phase = z["phase"]
plt.imshow(phase, cmap="twilight", vmin=0, vmax=2*np.pi)
plt.colorbar(label="Phase [rad]")
plt.axis("off")
plt.savefig("real_rbc_phase.png", dpi=200, bbox_inches="tight")
plt.show()
```

## 8. 출력 파일 읽는 법

| 파일 | 의미 |
|---|---|
| observation/sensor_only.npz | 역복원 입력: 실제 또는 합성 intensity |
| observation/private_truth.npz | 합성 정답; 복원에는 사용 금지 |
| observation/generation.json | 원본 데이터 해시, 파장, noise seed, 물리 조건 |
| inverse/gd_sealed.npz | 1단계 완료 위상 |
| inverse/recovered.npz | 최종 phase, wavelength_nm, scale |
| inverse/predicted.npz | 최종 예측 sensor |
| inverse/history.json | 반복별 objective 및 기록된 sensor L2 |
| inverse/recovery.json | 실행 방법, 반복 수, 해시, 종료 상태, 센서 오차 |
| inverse/evaluation.json | 합성 정답 기반 phase RMSE, ROI, 층별/집단별 RMSE, 합격 여부 |
| inverse/five_panel.png | 관측/예측 speckle, 정답, 복원, circular error |
| inverse/convergence.png | 기록된 sensor L2 수렴 그래프 |
| inverse/blind_scan.json | Blind 파장 후보 점수 |
| inverse/comparison_recovery.json | 비교 실행의 두 복원 감사 기록 |
| inverse/comparison_evaluation.json | 비교 실행의 두 사후 평가 결과 |

`single`의 기준 폴더는 위의 구조를 사용한다. 독립 `recover`는 지정한 output 바로 아래에 inverse 파일을 저장한다.
compare 모드에서는 각 방법 하위 폴더에 개별 결과가 저장되며 공통 파장 탐색 기록은 상위 폴더에 저장된다.
Pyramid의 L-BFGS legacy history는 objective만 제공하는 중간 기록이 있으므로, 해당 점을 sensor L2로 표시하지 않는다. 마지막 L2와 GD 기록으로 그래프를 만든다.
실제 측정에서는 정답 기반 평가 파일 및 five-panel이 생성되지 않는다.

```powershell
Get-Content 싱글/결과/rbc_triple660_spectral/inverse/recovery.json
Get-Content 싱글/결과/rbc_triple660_spectral/inverse/evaluation.json
Invoke-Item 싱글/결과/rbc_triple660_spectral/inverse/five_panel.png
```

## 9. 알고리즘과 물리 조건

공통: 원본 B17 LUT/width map, ASM/SAS, 전파 3800², 메타 1429², 물체 512², 센서 3000², 물체 피치 350 nm, 센서 피치 2 µm, 물체–메타 400 µm, 메타–센서 5 mm, 물체 진폭 1. 합성 센서 noise는 평균 clean intensity의 1% Gaussian, 비음수 clipping.

Spectral: 초기 GD100 무정규화, 이후 circular α=.015, FFT 기반 역사적 660 nm 민감도 보정, 100 accepted L-BFGS updates 목표. 다른 파장의 preconditioner 성능은 미검증.

Pyramid: 64/128/256/512 변수 격자에 35/35/40/40 GD. 광학 격자 자체는 모든 단계에서 그대로 유지한다. 첫 100회 무정규화, 이후 α=.015 circular prior. 기존 SciPy L-BFGS-B 최대150회. 역사적 피라미드의 보간/최적화는 연속적인 real-valued lift를 내부적으로 사용한다. 광학 forward/adjoint 호출과 최종 저장 phase는 mod 2π를 적용한다. 임시 legacy checkpoint는 종료 시 삭제하고 wrapped 복사본만 결과로 남긴다. 실제 물리 위상에 signed 영역이나 unwrap을 요구하는 방식이 아니다. 내부 변수까지 음수를 금지하는 엄격한 조건이면 Spectral을 선택한다.

평가: 전역 piston offset 정렬 후 circular error로 RMSE 계산. 0과 2π는 같은 복소 위상이다. 위상 컬러맵의 색상 경계만 보고 실제 오류로 판단하지 않는다.
통과 기준: full RMSE ≤.15 rad, sensor L2 ≤.025(2.5%), wavelength error ≤.5 nm, 목표 반복 완료. RBC는 ROI/존재하는 각 층/모든 집단 RMSE ≤.15 rad도 요구한다.
실제 측정에서 sensor L2만으로 위상 정확도 또는 합격 여부를 확정할 수 없다.

## 10. 기존 성능과 현재 개발 범위

| 실험 | 역사적 성능 |
|---|---|
| 660 nm RBC Full GD100 + Spectral100 | full .029155, ROI .077086 rad, 49/50 그룹 |
| 동일 RBC Pyramid150 + L-BFGS150 | ROI .084559 rad, 49/50 |
| 동일 RBC Pyramid150 + Spectral100 | ROI .083631 rad, 49/50 |
| 일반 이미지 과거 Pyramid64 | 독립 16-case 합성 benchmark 16/16 pass |

RBC 기준 그룹31은 여전히 실패(.329843 rad). 신규 통합 runner로 독립 장면/파장/Blind까지 검증한 결과가 아니다.
Pyramid의 새 공통 인터페이스는 역사적 코드의 알고리즘을 재사용하지만 물리 phase wrapping adapter와 출력 계약이 추가됐으므로 기존 수치를 자동 승계하지 않는다.
기존 결과 및 [동결된 RBC 기준](../benchmarks/single_reference/README.md), [연구 결정](연구기록/개발방향.md)을 보존한다. 기존 일반 이미지 Pyramid 검증은 과거 저장소의 실험 결과이며 신규 이식 코드의 결과가 아니다.
Multi/Continuous inverse는 이 변경 범위에 포함하지 않는다.

## 11. 오류 대처 및 검증

- FileExistsError: output 폴더를 새 이름으로 바꾼다. 기존 결과를 덮어쓰지 않는다.
- B17 archive absent 또는 LUT/width-map mismatch: 원본 ZIP 경로와 내부 데이터 무결성을 확인한다.
- Known inverse requires --wavelength: Known 모드의 실제 알려진 파장 값을 입력한다.
- Blind inverse must not receive wavelength: --wavelength 옵션을 제거한다.
- Auto recover requires --object-type: rbc/general 중 알려진 종류를 입력하거나 방법을 직접 선택한다.
- Expected nonnegative nonzero full 3000x3000 intensity: 센서 shape, NaN/inf, 음수, 영점 배열을 점검한다.
- Armijo exhausted / early termination: 로그와 recovery.json을 확인한다. 중간 결과를 목표 반복을 끝낸 성공으로 기록하지 않는다.
- 메모리 부족: 다른 계산을 종료하고 한 케이스씩 실행한다. 성능 비교를 위해 광학 격자를 임의 축소하지 않는다. 비교 모드는 순차 실행한다.

```powershell
python -m py_compile 싱글/코드/solver.py 싱글/코드/pyramid.py 공통/object_models.py
python -m tests.test_single_method_routing
python -m tests.test_contract
```

위 테스트는 라우팅/입력 계약과 기존 수치 연산의 단위 검증이다. 실제 전체 격자 복원 검증을 대신하지 않는다.
전체 성능 확인에는 3~6절의 실행 명령을 사용하고, 새 결과에 대해 sensor SHA와 RMSE를 비교한다.

## 12. 팀 개발 규칙

1. 원본 광학 데이터·기존 MAIN·역사적 결과를 보존한다.
2. 적혈구는 Spectral을 기준으로 개선한다. 일반 이미지는 Pyramid를 기본 후보로 유지한다.
3. 실제 복원 과정에 정답 phase, 실제 미지 파장, 정답 그룹 map을 공급하지 않는다.
4. 신규 알고리즘 채택 전 동일 센서·파장·광학 조건의 성능과 계산량을 비교한다.
5. 정답 평가 없이 선택한 방법과 정답을 알고 사후 비교한 결과를 명확히 분리한다.
6. 큰 생성 배열, 소유자 LUT 자료, private_truth를 새로 GitHub에 커밋하지 않는다.
